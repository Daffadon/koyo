# Koyo UI audit 001

Date: 2026-11-18
Scope: native desktop UI in `koyo/src/app`, light and dark themes, shell, sidebar, tabs, editor, data grids, dialogs, AI panel, and copy.
Mode: AFTER audit. No UI changes made.

## Direction

No `DESIGN.md` or equivalent written direction exists. The current UI reads as a calm database utility, with a warm paper light theme, a phthalo-green logo, sage accents, and monospaced data. Those are real choices, but the direction and the three dials are not recorded.

Working read for this audit, inferred from the current UI: ENERGY 1, RHYTHM 1, MOTION 1.

## Findings

### 1. Light theme muted text misses WCAG AA
Rule: R-25, R-34
Priority: HIGH
Evidence: `koyo/src/app/theme.rs:53` sets `muted_foreground` to `#74796F`. Measured against `background` `#F2F0E9`, `panel` `#F8F6F0`, and `sidebar` `#EAE7DD`, it is 3.91:1, 4.13:1, and 3.61:1. It is used at `text_xs` for table headers, field labels, subtitles, footer status, and empty-state detail, for example `koyo/src/app/views/table/grid.rs:318` and `koyo/src/app/views/widgets.rs:301`.
Reason: normal text needs 4.5:1. The light theme's secondary text fails at its most common size.

### 2. Light theme warning and danger text miss WCAG AA
Rule: R-25, R-34
Priority: HIGH
Evidence: `#A9783F` warning text is 3.01:1 on `panel_alt` `#E7E3D8` and 3.57:1 on `panel` `#F8F6F0`. It is used for normal-size text such as the pending-change badge (`koyo/src/app/views/table/mod.rs:189`) and the Oracle beta notice (`koyo/src/app/views/query/mod.rs:446`). Danger `#A85E57` is 4.41:1 on `panel`, used for error text such as `Query failed`.
Reason: these are normal-size status and error messages, not large text. The light theme makes warning and error copy harder to read.

### 3. Light theme focus ring and input boundaries fail non-text contrast
Rule: R-25, R-32, R-34
Priority: HIGH
Evidence: `koyo/src/app/theme.rs:74` sets `ring` to `#8AA69A`, which is 2.30:1 on `background`. The input component uses the ring token for the focused border and draws a focus ring at 50% opacity. `koyo/src/app/theme.rs:73` sets `input` to `#CFC9BC` (1.53:1 on `panel`), and `border` is `#D5D0C3` (1.35:1 on `background`).
Reason: focus indicators and control boundaries need 3:1 against adjacent colors. The light theme's focus and input boundaries are below that.

### 4. Custom clickable rows and cells are mouse-only
Rule: R-32, R-39
Priority: HIGH
Evidence: schema tree rows are clickable `div`s (`koyo/src/app/views/sidebar.rs:292`), history rows are clickable `div`s (`koyo/src/app/views/sidebar.rs:488`), table cells are clickable `div`s (`koyo/src/app/views/table/grid.rs:324`), query cells and row rails are clickable `div`s (`koyo/src/app/views/query/grid.rs:198` and `koyo/src/app/views/query/grid.rs:224`), and sortable headers are clickable `div`s (`koyo/src/app/views/table/grid.rs:70`). None has a focus handle, keyboard activation, or native control role.
Reason: keyboard users cannot expand schemas, open history, copy result cells, open a cell editor, or sort a table. A database grid without keyboard navigation is incomplete.

### 5. Icon-only controls have no accessible names
Rule: R-39
Priority: HIGH
Evidence: no `accessibility_label` or `aria_label` call exists in `koyo/src`. Icon-only buttons rely on visual tooltips only, for example the theme, collapse, refresh, and copy controls (`koyo/src/app/views/sidebar.rs:606`, `koyo/src/app/views/table/mod.rs:252`, and `koyo/src/app/views/query/mod.rs:317`).
Reason: tooltips are visible hints, not guaranteed accessible names. An icon-only button without a label is announced as an unnamed control.

### 6. Search and AI fields rely on placeholders instead of visible labels
Rule: R-39
Priority: HIGH
Evidence: the explorer filter is created with only `placeholder("Search tables")`, the profile filter with only `placeholder("Search saved connections")`, and the AI composer with only `placeholder("Ask about your database...")` (`koyo/src/app/actions/workspace.rs:54` and `koyo/src/app/actions/workspace.rs:66`). The table filter has a visible `Filter` label and does not share this defect.
Reason: a placeholder disappears as soon as the user types, and it is not a durable visible field label.

### 7. Explorer has no loading state and shows a false empty state
Rule: R-27
Priority: HIGH
Evidence: `load_tables` starts async metadata work without a loading flag (`koyo/src/app/actions/connections.rs:55`). While the request is in flight, `objects` and `metadata_groups` are empty, so the explorer shows `No metadata found.` (`koyo/src/app/views/sidebar.rs:423`).
Reason: the user sees an empty result before the data arrives and cannot tell whether the database has no objects or the app is still loading.

### 8. Initial table load is an unlabeled spinner
Rule: R-27, R-39
Priority: HIGH
Evidence: `loading_state` renders only a centered `Spinner` with no text (`koyo/src/app/views/table/mod.rs:15`). It is used when a table tab has no page yet and is loading.
Reason: a bare spinner does not say what is loading, and a screen reader has no status text. It reads as a frozen view on slow connections.

### 9. Query history success and failure are color-only
Rule: R-25, R-39
Priority: HIGH
Evidence: each history row draws a 6px dot with `success` or `danger` and no text or icon (`koyo/src/app/views/sidebar.rs:501`). The rest of the row shows SQL, age, profile, and duration, but not success or failure.
Reason: color alone carries the status. Color-blind and low-vision users cannot read it, and it disappears in forced-color contexts.

### 10. No written design direction or declared dials
Rule: R-37
Priority: HIGH
Evidence: no `DESIGN.md`, brand note, or equivalent direction exists. The three dials are not declared, and the decisions behind the paper palette, sage accent, phthalo logo, radii, and spacing are not written down.
Reason: the current UI has a recognizable calm identity, but it is not a documented direction. Under this rule it is still a draft-without-direction state, and future UI work has no authority to build against.

### 11. UI typeface has no documented rationale
Rule: R-06
Priority: MEDIUM
Evidence: the UI uses the theme's default sans face. Only the data face is chosen explicitly, through `cx.theme().mono_font_family` for grids and SQL results.
Reason: monospace for data is justified by the content. The base UI face is inherited rather than chosen, so the typographic identity is weaker than the palette and logo.
